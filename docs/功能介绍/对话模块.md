## 2. 场景一：答疑 (Q&A)

### 描述

用户直接提问，AI 以专业讲师风格回答。最基础的场景，也是使用频率最高的入口。

### 用户意图示例

```
"二次函数顶点怎么求？"
"什么是牛顿第二定律？"
"现在完成时和过去时的区别？"
```

### 对话流程

```
用户输入 ──▶ 路由到 chat / personal-explain skill
                │
                ├─▶ 检索 KB（如有相关文档）
                ├─▶ 读取 Memory（是否有历史记录）
                ├─▶ 生成回复（流式输出）
                └─▶ 附带引用来源（Citations）
```

### 交互要求

- 流式响应（打字机效果）
- KaTeX 公式渲染（数学/物理公式）
- 引用来源可点击追溯
- 支持多轮上下文

## 3. 场景二：学习规划 (Planning)

### 描述

AI 根据用户的掌握度数据、薄弱点和可用时间，自动生成每日/每周学习计划，包含具体任务项和预估时间。

### 用户意图示例

```
"帮我规划今天的复习"
"这周我每天有 30 分钟，怎么安排？"
"考前冲刺计划"
```

### 对话流程

```
用户输入 ──▶ learning-plan skill
                │
                ├─▶ 读取 LearnerState.mastery（各主题掌握度）
                ├─▶ 读取 LearnerState.weakPoints（薄弱点）
                ├─▶ 读取 LearnerState.preferences（偏好设置）
                ├─▶ 生成 PlanTask[]（任务列表 + 排序）
                └─▶ 写入 LearnerState.goals
```

### 交互要求

- 对话中展示**任务卡片**，每项含标题、预估时间、类型标签
- 卡片可勾选完成状态
- 点击任务可跳转到对应页面（学习/练习）
- 计划变更时自动更新 Dashboard

### 消息结构

```json
{
  "skill": "learning-plan",
  "content": "根据你当前的掌握度，我建议今天的安排是：",
  "tasks": [
    { "id": "t1", "title": "二次函数 · 精通路径", "estMinutes": 20, "type": "learn" },
    { "id": "t2", "title": "错题重练 · 3 道", "estMinutes": 15, "type": "practice" },
    { "id": "t3", "title": "英语阅读 · 1 篇", "estMinutes": 20, "type": "review" }
  ],
  "citations": [{ "source": "LearnerState · mastery[]", "snippet": "二次函数 0.42" }]
}
```

## 4. 场景三：作业辅导 (Coaching)

### 描述

用户遇到不会做的题目，AI 不直接给答案，而是通过苏格拉底式分步引导，帮用户自己找到解题思路。

### 用户意图示例

```
"这道题我不会"
"第二步怎么走？"
"我算出来是 3，但答案是 5，哪里错了？"
```

### 对话流程

```
用户输入 ──▶ homework-coach skill
                │
                ├─▶ 读取 Mastery（当前掌握度，调整引导深度）
                ├─▶ 分步输出 StepTrace[]
                │      step 1: 确认题目类型
                │      step 2: 列出已知量
                │      step 3: 选择相关公式
                │      step 4: 代入计算
                └─▶ 写入 recentActivity
```

### 交互要求

- 分步步骤以**可展开/收起的折叠面板**展示
- 每步可单独追问（"展开讲这一步"）
- 用户完成一步后自动推进下一步
- 支持在对话中**上传作业图片/PDF**

### 消息结构

```json
{
  "skill": "homework-coach",
  "content": "我们分步来，先不急着想答案：",
  "steps": [
    { "step": "先确认这是什么类型的问题", "detail": "函数？几何？" },
    { "step": "把已知量列出来", "detail": "" },
    { "step": "想想哪个公式和这些量相关", "detail": "" }
  ]
}
```

## 5. 场景四：错题诊断 (Diagnosis)

### 描述

用户做错题后，AI 自动分析错因（知识点薄弱 / 粗心 / 概念混淆），将诊断结果写入薄弱点，并安排针对性练习。

### 用户意图示例

```
"我又做错了，为什么？"
"这道题我选的 A，答案是 C"
"总是错在符号上"
```

### 对话流程

```
用户输入 / 批改触发 ──▶ error-diagnosis skill
                          │
                          ├─▶ 读取 ErrorBook（错题历史）
                          ├─▶ 读取 Memory（历史错误模式）
                          ├─▶ 分析错因（cause）
                          ├─▶ 生成 remedy（补救方案）
                          ├─▶ 写入 weakPoints（薄弱点更新）
                          └─▶ 写入 mastery（掌握度调整）
```

### 交互要求

- 展示**诊断结果卡片**：错因 → 证据 → 补救方案
- 诊断结果与 Dashboard 薄弱点联动更新
- 点击"安排练习"直接触发 adaptive-practice

### 消息结构

```json
{
  "skill": "error-diagnosis",
  "content": "核心是「符号错误」——把顶点横坐标 -b/2a 误写成 b/2a。",
  "diagnosis": {
    "cause": "符号方向错误",
    "evidence": "符号错误 3 次，集中在 -b/2a",
    "remedy": "安排 1 道针对练习巩固"
  },
  "citations": [{ "source": "Memory L1", "snippet": "符号错误 3 次，集中在 -b/2a" }]
}
```

## 6. 场景五：个性化讲解 (Explanation)

### 描述

AI 根据用户当前掌握度，对指定概念进行多角度讲解（直观理解 + 严格推导），并可按需追问或出配套练习。

### 用户意图示例

```
"解释一下顶点公式"
"判别式是什么？能不能用大白话讲？"
"给我一个生活中的例子理解这个"
```

### 对话流程

```
用户输入 ──▶ personal-explain skill
                │
                ├─▶ 读取 Mastery（当前掌握度，决定讲解深度）
                ├─▶ 读取 Preferences（学习偏好设置）
                ├─▶ 生成讲解（直观 + 严格 双视角）
                └─▶ 可选：生成配套练习
```

### 交互要求

- **KaTeX 公式渲染**（核心要求，当前纯文本无法展示公式）
- 支持多角度展开（"再讲详细一点" / "换个角度"）
- 讲解后自动询问是否需要配套练习

## 7. 场景六：自适应出题 (Quiz)

### 描述

AI 按用户薄弱点自动生成练习题，支持在对话中直接作答和批改，形成"出题 → 作答 → 批改 → 诊断"闭环。

### 用户意图示例

```
"出一道二次函数的题"
"再难一点"
"我做完了，答案是 (2, -1)"
```

### 对话流程

```
用户输入 ──▶ adaptive-practice skill
                │
                ├─▶ 读取 weakPoints（薄弱点，确定出题方向）
                ├─▶ 读取 mastery（掌握度，确定难度）
                ├─▶ 生成 Question[]（选择题/填空题/开放题）
                ├─▶ 用户作答 → gradeAnswer 批改
                ├─▶ 写入 mastery（根据对错更新掌握度）
                └─▶ 写入 errorBook（如答错）
```

### 交互要求

- 对话中**内嵌题目交互组件**：
  - 选择题：选项按钮，点击后高亮/反馈对错
  - 填空题：输入框 + 提交按钮
  - 开放题：文本输入 + 人工评判
- 答完一题后自动出下一题（自适应调整难度）
- 批改结果附带解析

### 消息结构

```json
{
  "skill": "adaptive-practice",
  "content": "先来第 1 题：",
  "question": {
    "type": "choice",
    "prompt": "抛物线 y = x² - 4x + 3 的顶点坐标是？",
    "options": ["(2, -1)", "(2, 1)", "(-2, -1)", "(4, 3)"],
    "answer": "(2, -1)",
    "explanation": "配方 y = (x-2)² - 1，顶点 (2, -1)"
  }
}
```

## 8. 场景七：错题归纳 (Summary)

### 描述

AI 按时间范围（周/月/全部）聚合错题数据，输出错误类型分布、趋势和针对性建议。

### 用户意图示例

```
"总结我这周错题的规律"
"我最近主要在哪些地方犯错？"
"这周比上周有进步吗？"
```

### 对话流程

```
用户输入 ──▶ mistake-summary skill
                │
                ├─▶ 读取 ErrorBook（错题数据）
                ├─▶ 读取 weakPoints（薄弱点）
                ├─▶ 聚合分析：错误类型 × 频率 × 趋势
                ├─▶ 写入 weakPoints（更新薄弱点）
                └─▶ 写入 mastery（调整掌握度）
```

### 交互要求

- 展示**统计图表/聚合视图**：
  - 错误类型分布（柱状图/饼图）
  - 趋势（周 vs 周对比）
  - 高频错误知识点 Top N
- 每类错误可点击展开详情

### 消息结构

```json
{
  "skill": "mistake-summary",
  "content": "本周错题归纳：",
  "patterns": [
    { "type": "符号/正负号错误", "count": 5, "trend": "stable" },
    { "type": "概念混淆", "count": 2, "trend": "improving" }
  ],
  "suggestion": "建议优先补「符号与正负号」类，预计 2 天可显著改善。"
}
```

## 9. 场景八：知识库引用 (RAG)

### 描述

AI 在回答时引用知识库中的原文作为依据，用户可上传文档（PDF/图片/文本）让 AI 阅读后回答问题。

### 用户意图示例

```
"从数学知识库里查一下判别式"
"读一下这份 PDF 总结重点"
"根据知识库回答：一元二次方程求根公式"
```

### 对话流程

```
用户上传文档 / 提问 ──▶ KB RAG 检索
                          │
                          ├─▶ 检索指定 KB（多引擎：LlamaIndex/PageIndex/...）
                          ├─▶ 获取相关 chunk + 原文 locator
                          ├─▶ 生成回复 + 引用标记
                          └─▶ 引用来源可点击跳转到原文位置
```

### 交互要求

- **附件上传**（Paperclip 按钮当前为空，需实现）
  - 支持 PDF、图片、文本文件
  - 上传后自动索引并关联到对话上下文
- 引用来源（Citations）可点击：
  - 跳转到 KB 原文位置
  - 显示来源 KB 名称和 chunk 位置
- 支持指定 KB 范围（"只查数学知识库"）

## 10. 当前能力与差距

### 当前实现 (`/home`)

| 功能 | 状态 | 说明 |
|------|------|------|
| 纯文本对话 | ✅ | 消息气泡 + 引用块 |
| 静态建议词 | ✅ | 4 条预设 |
| 流式响应 | ❌ | 无打字机效果 |
| KaTeX 公式渲染 | ❌ | 公式只能纯文本描述 |
| 附件上传 | ❌ | Paperclip 按钮为空 |
| 任务卡片 | ❌ | 规划结果只能文本展示 |
| 分步步骤 | ❌ | 辅导步骤只能文本展示 |
| 内嵌题目 | ❌ | 出题只能文本展示 |
| 诊断卡片 | ❌ | 诊断结果只能文本展示 |
| 统计图表 | ❌ | 归纳结果只能文本展示 |
| 工具执行 | ❌ | 代码/公式执行结果展示 |

### 差距分析

当前对话模块本质上是一个**通用聊天框**，所有 Skill 的输出都以纯文本形式展示。要真正支持 8 大场景，需要在消息渲染层增加**富内容组件**：

- **流式文本** → 基础体验，所有场景都需要
- **公式块** → 讲解、答疑、出题、辅导
- **任务卡片** → 规划
- **步骤面板** → 辅导
- **诊断卡片** → 诊断
- **题目组件** → 出题
- **统计摘要** → 归纳
- **附件预览** → 知识库引用

## 11. 实现优先级

### P1 — 基础体验

| 功能 | 依赖 | 场景 |
|------|------|------|
| 流式响应 | 后端 WebSocket | 所有场景 |
| KaTeX 公式渲染 | `katex` npm 包 | 答疑、讲解、出题、辅导 |
| 附件上传 | 后端文件上传接口 | 知识库引用、作业辅导 |

### P2 — 场景深化

| 功能 | 依赖 | 场景 |
|------|------|------|
| 内嵌题目交互 | 前端选择题/填空题组件 | 出题 |
| 任务卡片 | 前端任务列表组件 | 规划 |
| 分步步骤面板 | 前端折叠面板组件 | 辅导 |
| 诊断结果卡片 | 前端诊断卡片组件 | 诊断 |

### P3 — 高级能力

| 功能 | 依赖 | 场景 |
|------|------|------|
| 统计图表 | 前端图表库（recharts） | 归纳 |
| 工具执行展示 | 后端 tool-ui 执行环境 | 代码/公式执行 |
| 多模态输入 | 图片/语音输入 | 全场景 |
