## 0. 背景与范围

- **对话模块（`/home`）是核心交互入口**：`对话模块.md` 的 8 场景全部在此发生，全部由「6 Skills + KB RAG + Memory + Mastery」驱动。
- **现状缺口**：当前 `sendMessage`（`mock.ts:268-310`）只做关键词路由→纯文本 canned 回复；**不写记忆、不读 Mastery 调深度、不出结构化富内容、不流式、无附件**。8 场景里只有「纯文本对话」做出来了（`对话模块.md:401-414`）。
- **本文目标**：把 8 场景从「概念」落到「后端逻辑 + 共享服务 + 端点契约 + 富内容载荷 + 2 个端到端案例」。

**三条铁律**：
1. **契约一致**：贴合 `PlosApi`（`types.ts:260-292`）。
2. **单写者**：`mastery`/`weakPoints` 唯一权威写入者 = **MasteryEngine**；Skill 与批改只产 `LearnerStateDelta`（`types.ts:118-121`），由 MasteryEngine 落库（`API协议.md:87`）。
3. **知名开源组件优先**：基座 DeepTutor；记忆 mem0；掌握度 pyBKT；闪卡 py-fsrs；RAG = LlamaIndex+pgvector+bge-reranker；网关 LiteLLM。

**身份/阈值**（`API协议.md:43-60`）：`learnerId` 由 PocketBase token 派生，不信任客户端 id；`weakPoints = level<0.6`；`mastery∈[0,1]`；错误信封 `{error:{code,message,details}}`；ID 形如 `<type>_<ulid>`。

## 3. 对话模块主链路（统一管线）

**主入口**：`POST /api/threads/{threadId}/messages`，body `{ learnerId, content, persona }`，返回 `ChatMessage`（`types.ts:168-176`、`client.ts:88`）。流式版 `WS /ws/chat`（待实现；事件见 §3.3）。

**每轮统一管线（8 场景共用）**：

```
用户输入（+ thread 上下文 + persona + 附件?）
 │
 ① 技能路由：DeepTutor agent loop 发 skill 事件 → 8 场景之一
 │
 ② 知识检索 RAG [LlamaIndex+pgvector+bge-reranker]（场景1/5/8 必需，其它可选）
 │   query → 混合检索(向量 BGE-M3 + BM25) → 重排 → Top-K 片段(带 locator)
 │
 ③ 个性化上下文组装：
 │   · mem0.search(query) → 相关 L2 事实 / L3 策略（场景1/4/5 受益最大）
 │   · 读 LearnerState：主题 mastery、是否 weakPoint、已知 misconception
 │   · persona + preferences.difficulty
 │
 ④ 生成 [LiteLLM→LLM]：在 [②检索片段 + ③个性化上下文 + persona + 场景指令] 下产出
 │     · 场景1/5：讲解文本，按 mastery 调深度（<0.4 拆步骤 / 0.4–0.7 正常+随堂测 / >0.7 迁移）
 │     · 场景2/3/6/7：结构化对象（tasks/steps/question/patterns）+ 引导文本
 │     · 公式以 LaTeX 原样输出（$...$ / $$...$$），后端不转义 $
 │
 ⑤ 输出 ChatMessage：content + payload?(结构化) + citations[] + skill + status
 │
 ⑥ 沉淀（异步）：本轮落 L1 → mem0 抽 L2（轮末）→ 会话末合成 L3
```

### 3.1 〔协议扩展建议〕富内容载荷契约（核心缺口）

`对话模块.md` 每个场景的「消息结构」都带结构化字段，但现 `ChatMessage`（`types.ts:168-176`）只有 `content + citations + skill + status`，**装不下**。建议扩展（向后兼容，全部可选）：

```ts
// 在 ChatMessage 上新增可选 payload（与 SkillResult.output 同形）
export interface ChatMessage {
  id: string; role: MessageRole; content: string; createdAt: string;
  citations?: Citation[]; skill?: SkillId; status?: MessageStatus;
  payload?: ChatPayload;   // 〔扩展〕结构化富内容，按 skill 判别
}

export type ChatPayload =
  | { kind: "plan";      tasks: PlanTask[] }                       // 场景2 learning-plan
  | { kind: "coach";     steps: { step: string; detail?: string }[] } // 场景3 homework-coach
  | { kind: "quiz";      question: Question }                      // 场景6 adaptive-practice
  | { kind: "diagnosis"; diagnosis: { cause: string; evidence: string; remedy: string } } // 场景4
  | { kind: "summary";   patterns: { type: string; count: number; trend: Trend }[]; suggestion: string }; // 场景7
// 场景1/5/8 不带 payload，仅 content + citations
```

- `payload` 在 REST `sendMessage` 响应与 `/ws/chat` 的 `done` 事件中都携带。
- 与 `SkillResult.output`（`types.ts:151-159`，本就是 `Record<string,unknown>`）一致：对话路径 = skill 经 Agent loop 执行后，把 `output` 投影成 `payload` 挂到消息上。

### 3.2 个性化答疑（场景1/5/8 的「个性化」语义）

- **知识提问**（场景1/8）由 ② RAG 保证：基于 `kb_documents` 检索，答案有据、`citation.locator` 回链 PDF 页。
- **个性化讲解**（场景1/5）由 ③④ 保证：读主题 mastery 调深度 + 引用该生记忆（「你上次把 `-b/2a` 符号写错过，这里自检」），并以 `citation.source="Memory L2·…"` 回传——**复用前端已有 citation 渲染（`home/page.tsx:190-199`），零前端改动**。

### 3.3 流式协议 `WS /ws/chat`（P1 依赖）

对齐 `API协议.md:204-220`，NDJSON 事件：

| 事件 | 时机 | 载荷 |
|---|---|---|
| `skill` | 路由完成 | `{ skill: SkillId }` → 前端显示 skill 徽章 |
| `content` | 文本增量（含 LaTeX） | `{ delta: string }` → 打字机 + KaTeX 增量渲染 |
| `citation` | 检索到来源 | `Citation` |
| `tool_call`/`tool_result` | Agent 调用 RAG/记忆工具 | `{ tool, args?, result? }` |
| `payload` | 结构化富内容就绪 | `ChatPayload`〔扩展：原协议未列，建议新增〕 |
| `done` | 本轮结束 | `{ messageId }` |
| `error` | 失败 | `{ code, message }` |

20s ping/pong、断线自动重连。`payload` 事件用于在文本流同时/之后推送 `tasks`/`steps`/`question`/`diagnosis`/`patterns`，前端按 `kind` 渲染对应富组件。

### 3.4 附件上传（场景8 P1 依赖）

现 Paperclip 按钮为空（`home/page.tsx`）。后端新增：
- `POST /api/threads/{threadId}/attachments`（〔协议扩展建议〕）：multipart 上传 PDF/图片/文本 → MinerU/Docling 解析 → 入临时 KB → 关联 thread 上下文。后续该 thread 的 ② RAG 自动覆盖此附件。

## 4. 8 场景后端逻辑（逐场景）

> 每个场景：触发意图 → 路由 skill → 读写 → 结构化输出。消息结构直接对齐 `对话模块.md`。

### 场景 1 答疑 & 场景 8 知识库引用（合并：RAG 答疑）
- 路由：`chat` / `personal-explain`；若命中「查知识库/读 PDF」意图 → 走 KB RAG。
- 读：`mem0.search` + LearnerState.mastery；KB 检索（场景8 可指定 `kbIds`，见 `SkillRequest.context.kbIds` `types.ts:144`）。
- 写：`recentActivity`（经 `LearnerStateDelta`）。
- 输出：`content`（流式+KaTeX）+ `citations[]`（场景8 带 locator）。无 payload。

### 场景 5 个性化讲解
- 路由：`personal-explain`。
- 读：mastery（定深度）+ preferences（persona）。
- 输出：`content` 双视角（直观+严格推导），LaTeX 原样；可选追问「需要配套练习吗」→ 可转场景6。

### 场景 2 学习规划
- 路由：`learning-plan`。
- 读：`mastery`·`weakPoints`·`preferences`·`goals`。
- 写：**`goals`**（唯一写 goals 的 skill；`PlanTask` 见 `types.ts:55-62`）。
- 输出：`payload.kind="plan"`，`tasks[]`（标题/estMinutes/type/ref）。ref 可指向 book/quiz/cards（`types.ts:61`），供前端卡片点击跳转。

### 场景 3 作业辅导
- 路由：`homework-coach`。
- 读：mastery（调引导深度）。
- 写：`recentActivity`。
- 输出：`payload.kind="coach"`，`steps[]`（苏格拉底分步，不直接给答案）；支持附件（题目图片/PDF）。

### 场景 6 自适应出题（对话内闭环，见 UC-B）
- 路由：`adaptive-practice`。
- 读：`weakPoints`（定方向）+ `mastery`（定难度，§7.2）。
- 写：`mastery`（经 MasteryEngine，批改后）+ `errorBook`（答错入册）。
- 输出：`payload.kind="quiz"`，`question`（一次一题）；用户对话内作答 → `gradeAnswer`（§8）→ MasteryEngine 更新 → 下一题自适应（难度随 `P(L)` 升降）。

### 场景 4 错题诊断
- 路由：`error-diagnosis`（由批改 miss 或用户「为什么错」触发）。
- 读：`ErrorBook`·`Memory`（历史错误模式）·`mastery`。
- 写：`weakPoints`·`mastery`（经 MasteryEngine）；错因写回 `errorBook.errorType`。
- 输出：`payload.kind="diagnosis"`，`{cause, evidence, remedy}`；`citations` 指向 Memory L1。

### 场景 7 错题归纳
- 路由：`mistake-summary`。
- 读：`ErrorBook`（按 range：周/月/全部）·`weakPoints`。
- 写：`weakPoints`·`mastery`（经 MasteryEngine）。
- 输出：`payload.kind="summary"`，`patterns[]{type,count,trend}` + `suggestion`；前端用 recharts 渲染（`对话模块.md:454`）。

## 5. 横切能力①：基于对话的记忆管理（mem0）—— 共享服务写全

补齐文档缺失的「抽取/合并/溯源/触发」。**mem0 承担 L1→L2，自研薄层做 L3。**

### 5.1 三层模型与产出方

| 层 | 内容 | 产出方 | 存储字段（扩 `memory` 表，`API协议.md:269`） |
|---|---|---|---|
| **L1 traces** | 每轮原始痕迹（user/assistant/skill/tool_result/citation） | 同步落库 | `layer=L1, source=session:<thread>:<msg>, kind∈{user,assistant,skill,tool}, thread_id, message_id` |
| **L2 facts** | 提炼的持久事实 | **mem0 ADD/UPDATE**（自动抽取·embedding 去重·矛盾消解） | `layer=L2, kind∈{knowledge_gap,misconception,strength,preference,goal,context}, topic, confidence, status∈{active,superseded,resolved}, evidence:[L1…]` |
| **L3 synthesis** | 跨场景教学策略/模式 | 自研薄层 LLM 合成 | `layer=L3, strategy, evidence:[L2…]→L1` |

```python
from mem0 import Memory
m = Memory()  # 后端 pgvector + graph 存储
# 轮末：近期 L1 喂 mem0，自动抽/去重/合并 L2
m.add(messages=[{"role":"user","content":"我老把 -b/2a 写成 b/2a"},
                {"role":"assistant","content":"顶点横坐标是 -b/2a，符号别漏"}],
      user_id=learner_id, metadata={"thread_id":thread_id,"topic":"二次函数","kind":"misconception"})
hits = m.search(query="二次函数顶点公式", user_id=learner_id, limit=5)   # 主链路 ③ 注入
m.update(memory_id=fid, data="已掌握 -b/2a 符号（resolved）")            # 学生纠正后
```

### 5.2 触发时机（L1 同步、L2/L3 异步，绝不阻塞聊天）

| 触发事件 | 动作 | 层 | 同步性 |
|---|---|---|---|
| 每发一条消息（`sendMessage`） | 落 L1 + `mem0.search` 注入下一轮(③) | L1 写+L2/L3 读 | 同步(<50ms) |
| 单轮结束（去抖 3–5s/静置） | `mem0.add` 抽 L2、去重消解 | L1→L2 | 异步(秒级) |
| 会话结束/切 thread/闲置 10min | 本会话 L2 聚合 → L3 策略 | L2→L3 | 异步(分钟级) |
| 定时兜底（每日凌晨） | 补漏抽、重算 confidence 衰减 | 跨层 | 离线 |

### 5.3 会写 L1 的事件清单（统一管线）
chat 消息、`invokeSkill` 结果、**`gradeAnswer` 批改事件**（「做错几何证明第3题」→L1，并可触发 L2 错因事实）、闪卡 `POST /api/cards/{id}/review`（`/learn` 侧）、用户显式 `POST /api/memory`。

### 5.4 合并/消解（mem0 承担）
矛盾→旧者 `superseded`（记 `refutes` 边）；确认→`confidence` 衰减累加 `c'=1-(1-c)(1-Δ)`；重复→embedding 相似度>阈值丢弃。

### 5.5 Memory Graph
mem0 graph store 存节点(L1/L2/L3)+边(`derived_from`/`supports`/`refutes`/`supersedes`)；`GET /memory/graph` 返回 `{nodes,edges}` 供 react-flow 渲染。L3 可一路点回 L1 原始痕迹。

## 6. 横切能力②：动态个性化学习 —— MasteryEngine（pyBKT）共享服务写全

### 6.1 算法（落地 `模块方案.md:77` 的「BKT 或 FSRS 衍生」）
- **决策：pyBKT 管每主题掌握度 + py-fsrs 管闪卡调度**，按域分工。
- **每主题 4 参**：`P(L0)` 初始、`P(T)` 迁移、`P(S)` 失误、`P(G)` 猜中。
- **更新**（每次观测后贝叶斯 + 迁移）：
  - 对：`P(L|✓)=(1-P(S))·P(L)/[(1-P(S))·P(L)+P(G)·(1-P(L))]`，再 `P(L)←P(L|✓)+(1-P(L|✓))·P(T)`
  - 错：`P(L|✗)=P(S)·P(L)/[P(S)·P(L)+(1-P(G))·(1-P(L))]`，再 `P(L)←P(L|✗)+(1-P(L|✗))·P(T)`
- **软证据**：error-diagnosis 确认错因（加权「错」）、py-fsrs 卡片逾期（加权「遗忘」）。
- **衰减**：`P(L)←P(L)·e^(-Δt/half_life)`，`half_life` 关联 FSRS `stability`。
- **`trend`**：近 N 次 `ΔP(L)` → up/down/flat。
- **`weakPoints` 每次 commit 重算**（`level<0.6`）—— 修复 `mock.ts:33` 只构造时算一次的缺陷。
- **`overallMastery`**：各主题 `P(L)` 按近度·重要性加权聚合。

### 6.2 难度标定（场景6 出题 + `/practice`）
按目标主题 `P(L)` + `preferences.difficulty` 偏置：`<0.4→基础`、`0.4–0.7→中等`、`>0.7→迁移`。

### 6.3 边界（唯一写者）
内部服务、无直接写端点；消费 `LearnerStateDelta`（场景2/3/4/6/7 产的 sideEffects）+ 批改事件；经 `GET .../state` 暴露。**对话侧（场景6 内嵌批改）与 `/practice` 侧批改走同一 MasteryEngine。**

## 7. 共享服务：知识库 RAG（LlamaIndex + pgvector + bge-reranker）

- **入库**（`POST /api/kbs/{id}/documents`，`API协议.md:161`）：MinerU/Docling 解析 → LlamaIndex 切块 → BGE-M3 向量 → pgvector；记录 `locator`（PDF 页码/坐标）到 `kb_documents`（`API协议.md:273-278`）。
- **检索**（`POST /api/kbs/{id}/search`，`API协议.md:161`；对话内由 ② 自动调）：query → LlamaIndex hybrid（BM25 + 向量）→ bge-reranker → Top-K 片段 + locator。
- **多引擎**：`engine∈{llamaindex,pageindex,graphrag,lightrag,obsidian}`（`types.ts:191`），对话场景8 可指定。
- **溯源**：检索片段转 `Citation{id,source,snippet,locator}`（`types.ts:127-132`），前端点击跳原文。

## 8. 共享服务：语义批改（`POST /api/quiz/grade`）

- **choice** → 精确匹配。
- **fill** → 归一化（去标点/空格/大小写）+ 同义词集容错。
- **open** → LLM judge + rubric，返回档位 + 理由。
- 发批改事件 `{questionId,topic,correct,score?}` → MasteryEngine（pyBKT 更新）+ 错题本（miss 入册，`errorType` 初始 `"待诊断"`，由场景4 回填）。
- 〔协议扩展建议〕：`QuizResult`（`types.ts:226-231`）现仅 `correct:boolean`，建议增 `score?:number(0..1)`、`rationale?:string`；`correct` 不变以兼容 `practice/page.tsx`。

## 10. 使用案例（2 个端到端，含逐轮数据与数值演算）

### UC-A · 记忆管理（场景1答疑→场景4诊断→场景5讲解，跨 2 会话）

**会话1（thread_1）** 小李：「我老把顶点公式 `-b/2a` 写成 `b/2a`。」

1. **L1 落库**（同步）：
   ```json
   { "id":"mem_L1_01J…","layer":"L1","kind":"user",
     "content":"我老把顶点公式 -b/2a 写成 b/2a","source":"session:thread_1:msg_3",
     "thread_id":"thread_1","message_id":"msg_3","createdAt":"2026-08-13T10:02:11Z" }
   ```
2. ③ 检索暂未命中（首次）；按 mastery(二次函数 0.5) 走中等讲解，助手加正负号自检脚手架。
3. 轮末（异步）**mem0 抽 L2**：
   ```json
   { "id":"mem_L2_01J…","layer":"L2","kind":"misconception","topic":"二次函数",
     "content":"小李混淆顶点横坐标符号，误写 -b/2a 为 b/2a",
     "confidence":0.8,"status":"active","evidence":["mem_L1_01J…"],"createdAt":"2026-08-13T10:02:18Z" }
   ```

**会话间 → L3 合成**：
```json
{ "id":"mem_L3_01J…","layer":"L3",
  "strategy":"小李在『含符号公式』上反复出错（已见 -b/2a）；讲此类公式先做正负号自检再代入",
  "evidence":["mem_L2_01J…"],"createdAt":"2026-08-13T10:30:00Z" }
```

**会话2（thread_2，聊别的）** 小李：「讲讲完全平方公式。」
1. ③ `mem0.search("完全平方公式")` 召回相关 L3（含符号公式先自检）。
2. 助手**主动**：「你之前在含符号公式（如 `-b/2a`）易漏负号，完全平方 `(a±b)²` 的 `±2ab` 也注意符号。」`citation.source="Memory L3·synthesis"`。
3. 小李复述正确 → `mem0.update`：旧 L2 `status→resolved`，新增 L2 `{kind:strength,"能正确说出 -b/2a 符号"}`。

**Memory Graph 片段**：`L3#strategy ─derived_from─▶ L2#misconception(resolved) ─derived_from─▶ L1#msg_3`；`L2#strength ─refutes─▶ L2#misconception`。

### UC-B · 个性化学习（场景6 对话内出题闭环 + 场景4 诊断）

小李在 `/home`：「给我出一道几何证明题。」初始几何证明 `P(L0)=0.55`（weak），pyBKT 参 `P(T)=0.10,P(S)=0.30,P(G)=0.30`。

1. 路由 `adaptive-practice`；读 weakPoints（几何证明 0.55）→ 难度中等偏易；输出 `payload.kind="quiz"`，一道 choice 题。
2. 小李答 **错** → `gradeAnswer` `correct:false` → MasteryEngine pyBKT：
   `P(L|✗)=0.3·0.55/(0.3·0.55+0.7·0.45)=0.165/0.48=0.344`；迁移 `0.344+0.656·0.1=` **0.41**。
   `level 0.55→0.41`、`trend:down`、`errorCount+1`、仍 weak；错题入册 `errorType="待诊断"`。
3. 自动触发**场景4 诊断**：`payload.kind="diagnosis"` `{cause:"混淆全等与相似判定条件", evidence:"判定条件错 2 次", remedy:"安排基础辨析题"}`，`citation.source="Memory L1"`；`errorType` 回填。
4. 下一题自适应：`P(L)=0.41`（接近基础线）→ 降基础、仍 choice（降猜中噪声）。小李答 **对**：
   `P(L|✓)=0.7·0.41/(0.7·0.41+0.3·0.59)=0.287/0.464=0.618`；迁移 `0.618+0.382·0.1=` **0.66**。
   `trend:up`，`0.66>0.6` → 移出 weakPoints。
5. `/practice` 侧同周继续巩固（同一 MasteryEngine）：一周 `P(L)` 0.41→0.55→0.64→0.72（含隔夜衰减+复习）；`learning-plan`（场景2）据此把时长挪到下一弱项。

> 可验算：UC-B 第 2、4 步的 `P(L|✗)`、`P(L|✓)` 代入计算器可复现 0.41 / 0.66。

## 12. 关键技术决策与理由

1. **范围**：以 `对话模块.md` 8 场景为骨架；共享服务（MasteryEngine/mem0/RAG/FSRS）写全，对话侧与 `/practice`、`/learn` 侧共用。
2. **基座**：DeepTutor 提供原生 chat/KB/RAG/quiz，PLOS 在其上补 LearnerState/Skills/MasteryEngine（贴合「基于 DeepTutor」）。
3. **记忆用 mem0**：开箱提供抽取/去重/合并/检索/图，覆盖 L1→L2 + Memory Graph；自研仅 L3 薄层。
4. **掌握度 = pyBKT + py-fsrs 分工**：知名、可解释、属文档候选。
5. **富内容契约扩展**：`ChatMessage.payload`（判别联合）承载 8 场景结构化输出；与 `SkillResult.output` 同形，经 `/ws/chat` 的 `payload`/`done` 推送。
6. **单写者**：所有 `mastery` 变更经 `LearnerStateDelta` → MasteryEngine。
7. **零前端破坏**：所有扩展字段可选；记忆回流复用已有 citation 渲染。
