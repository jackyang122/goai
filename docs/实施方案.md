# Personal Learning OS — 实施方案

> 本文是工程落地的执行方案：当前已完成什么、如何分阶段交付、各阶段如何验收。接口契约见 [API协议.md](API协议.md)，模块级未来方案见 [模块方案.md](模块方案.md)。

---

## 1. 背景与目标

把 AI 从「问答工具」升级为「终身学习伙伴」。核心机制：**以 Learner State 为持久核心，单一 Learning Agent + 6 个可插拔 Skill 驱动所有学习动作**；辅导、解题、测验、研究、可视化、精通练习在同一 Agent 大脑上切换目标而非引擎。

**本次目标**：交付一个**完整可运行的 Demo**（端到端可点击、视觉对标原型），后端接口协议全部定义，具体模块逻辑可后续按协议实现。

## 3. 架构落地

### 3.1 目录结构

```
web/
├── app/                    # 路由
│   ├── layout.tsx          # 根布局：字体 + 主题 + AppShell
│   ├── page.tsx            # Dashboard（首屏）
│   ├── home/page.tsx       # 对话（Teacher）
│   ├── learn/page.tsx      # 学习（Book/Reader/Notebook/Cards）
│   ├── practice/page.tsx   # 练习（测验/批改/错题本）
│   └── me/page.tsx         # 我的（KB/Memory/Skills/Settings）
├── components/
│   ├── app-shell.tsx       # 侧边栏 + 顶栏
│   ├── theme-provider.tsx  # 亮/暗主题
│   └── ui/                 # 设计系统组件
├── lib/
│   ├── api/                # ★ 契约层
│   │   ├── types.ts        # 全量类型 + PlosApi 协议
│   │   ├── seed.ts         # 原型种子数据
│   │   ├── mock.ts         # Mock 后端（实现 PlosApi）
│   │   ├── client.ts       # mock / real 切换
│   │   └── index.ts        # barrel
│   ├── hooks.ts            # useLearnerState()
│   └── utils.ts            # cn / 格式化
└── next.config.mjs         # /api,/ws → DeepTutor 的 rewrites
```

### 3.2 数据流（统一走 `api` 单例）

```
页面组件 ──▶ lib/api (api 单例)
                │
       NEXT_PUBLIC_USE_MOCK?
        ├── true  ─▶ mockApi（内存，含 delay 模拟网络）
        └── false ─▶ RealApi（fetch → DeepTutor origin → FastAPI）
```

- 切换后端**零代码改动**：仅改环境变量。
- Mock 与 Real 实现同一 `PlosApi` 接口，类型完全一致。

### 3.3 关键设计决策

- **首页 = Dashboard**（用户确认）。对话 `/home` 通过顶栏「问 AI」与 Dashboard 互通。
- **简约风格**：中性 zinc 底 + 单一 indigo 强调色；掌握度用语义色（红<50% / 琥珀50-75% / 绿>75%）。
- **默认 Persona = Teacher**（环境变量 `NEXT_PUBLIC_DEFAULT_PERSONA`）。
- **LearnerState 为唯一数据中枢**：Dashboard/对话/练习都从它读、向它写。
- **MasteryEngine 是 mastery 的唯一写入方**，Skill 仅产出声明式 `sideEffects`。

## 4. 分阶段交付

### P0 — 地基（已完成）
- Next.js 工程、设计系统、应用骨架、接口契约层、Mock 后端。

### P1 — Dashboard 闭环（Demo 已就绪，待接真实数据）
- LearnerState 读写端点（`GET/PATCH /api/learners/{id}/state`）。
- 打通 `learning-plan`、`personal-explain`、`adaptive-practice` 三个 Skill。
- **验收**：Dashboard 全部 KPI 与推荐由真实数据驱动；首启 3 分钟见价值。

### P2 — 对话与知识库（接 DeepTutor 原生）
- `/ws/chat` 流式 + assistant-ui runtime。
- `/api/kbs` 创建/上传/检索（复用 DeepTutor Knowledge Center）。
- **验收**：上传 1 个 PDF → 建 KB → 对话中 RAG 引用可追溯原文。

### P3 — 检验闭环（Quiz + Mastery + Memory）
- Quiz 生成（`deep_question`）/ 批改 / 错题本 / 间隔重复闪卡。
- MasteryEngine（掌握度算法）+ Memory Graph 可视化。
- **验收**：答错 → 自动入错题本 → 触发闪卡 → 掌握度更新 → 路径调整。

### P4 — 深化与开放
- 多引擎 KB 全量（GraphRAG/LightRAG/PageIndex/Obsidian）。
- Deep Question 进阶、Partners / 子智能体、协作。
- **验收**：跨引擎检索一致；Partner 历史可导入。

## 5. 验收标准（端到端）

| 场景 | 验收点 |
|------|--------|
| 冷启动 | 登录即见 Dashboard，数据非空，3 分钟内可进入任一学习动作 |
| 对话 | 输入「二次函数顶点怎么求」→ Teacher 回复含步骤 + 引用来源 |
| 测验 | 生成 3 题 → 作答 → 批改 → 错题入本 → Dashboard 薄弱点更新 |
| 闪卡 | 点击翻转；待复习数与 Dashboard 一致 |
| 切换后端 | 仅改 `.env`，Mock↔Real 行为一致（无类型差异） |
| 构建 | `npm run build` 通过；5 路由全部静态预渲染 |

## 6. 风险与缓解

| 风险 | 缓解 |
|------|------|
| DeepTutor 端点与本文协议命名差异 | Real 客户端集中在 `client.ts`，后端就绪时仅需调路径；或在 DeepTutor 加薄适配层 |
| 流式聊天接入复杂 | 先用 REST 回执（已实现），`/ws` 作为 P2 增量 |
| 多 Skill 并发写 mastery 冲突 | MasteryEngine 单一写入方 + `sideEffects` 声明式 |
| 冷启动概念密集 | 首启引导：建 KB → 生书 → 推荐测验 |
